# Flight-delay generalisation across US airports

Bachelor's thesis experiment predicting departure delays of at least 15 minutes at US airports excluded from training. Development uses 2024 flights; final evaluation uses 2025 flights at ATL, CLT, DEN, DFW, LAS, LAX, LGA, ORD, PHX and SEA.

## Environment

The experiment used Python 3.14.3. Create a virtual environment and install the pinned environment:

```sh
python3 -m venv venv
source venv/bin/activate
python -m pip install -r requirements.txt
```

On macOS, XGBoost may additionally require the system OpenMP library (`brew install libomp`). Select this environment as the notebook kernel.

## Data and local-only files

See [DATA_PROVENANCE.md](DATA_PROVENANCE.md) for BTS and NOAA acquisition details. Raw and processed datasets, per-flight prediction CSVs, the virtual environment and `writing/` are deliberately excluded from Git. A clone includes code and summary results, not the full experiment inputs. Reproduction requires acquiring the documented datasets or supplying the local processed data and predictions.

## Workflow

Run notebooks with the project root or `notebooks/` as the working directory. Preparation uses the shared modules in `src/`.

| Notebook | Role |
|---|---|
| 01, 02 | Initial BTS inspection, full-year audits and airport selection |
| 03 | Prepare 2024 flight data |
| 04 | Initial ATL weather investigation and matching audit |
| 05 | Prepare and match weather for all 2024 airports |
| 06 | Historical model-development pilot; its saved LR scores support the reproduction check in 08 |
| 07 | Prepare 2025 flights and weather |
| 08 | Final tuning, prediction, metrics and original per-airport day-bootstrap analysis |
| 09 | Results figures and joint calendar-bootstrap analysis, including day/week sensitivity |
| 10 | Exploratory airport patterns; interpret as post-test exploration |
| 11 | Paper figures using the joint weekly-bootstrap results |

Notebooks 01, 02, 04 and 06 are retained as audit/development history, rather than redundant files to delete. Do not rerun training merely to view results. Preparation and training can overwrite generated outputs; tuning and final fitting are expensive.

## Results and statistical interpretation

`outputs/final_evaluation/airport_results.csv` and `overall_results.csv` contain test metrics. Overall means weight airports equally. `joint_bootstrap_contrasts.csv`, `equal_airport_mean_contrasts.csv` and `bootstrap_joint/` contain the later joint-bootstrap analysis. The weekly-block results are the primary paper-figure source; single-day results provide a sensitivity comparison. Original `reference_ap_intervals.csv` and `weather_ap_intervals.csv` are retained for the earlier day-bootstrap figures, not interchangeable with the joint analysis.

`figures/` contains PDF/PNG exports, including weekly figures from notebook 11. `exploratory/` contains supporting post-test analyses. Checkpoint metadata and tuning scores preserve experiment provenance. Obsolete name-only bootstrap checkpoint CSVs were removed; rerunning those notebook cells creates fingerprinted replacements. Existing aggregate interval tables were preserved.

Unseen models exclude the target airport's 2024 flights. References additionally include those flights using the same selected settings, so the comparison also changes training-set size. AP depends on prevalence; the constant baseline provides context. Bootstrap intervals condition on fitted models and the ten studied airports. Test results must not be reused for tuning while claiming an untouched final test.

## Reproducibility

Prediction files are located through `outputs/final_evaluation/predictions/manifest.csv` and are generated by notebook 08. They remain local because of their size. Changes to code/data/settings can invalidate checkpoints and trigger recomputation. Dependencies are pinned in `requirements.txt`; use a specific Git commit when citing the implementation.
